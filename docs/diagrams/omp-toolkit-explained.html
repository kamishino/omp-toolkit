OMP Toolkit

OMP Toolkit, explained

OMP pins an agent session to one provider account, so a hung route stalls the session even while sibling accounts stay healthy. This toolkit reads every provider's quota, records per-account route health, and moves a stalled Antigravity account out of the way until it recovers.

Monitoring and route health

Two inputs meet in one dashboard: quota reports fetched from the OMP CLI, and a saved health snapshot. The dashboard is compiled once and rendered either in a terminal or in the desktop panel; the desktop spawns that same CLI rather than rebuilding the data.

Displaying usage performs no model inference. The health extension's probe does, and quota or balance lookups still call provider APIs — so a route result describes that probed route, not every model on the account.

Gateway: control versus model traffic

OMP already ships the serving path: a forward proxy in front of a credential vault. The toolkit's gateway app manages those daemons and their policy; it holds no inference proxy of its own, so no model request passes through toolkit code.

OMP owns serving, the upstream OAuth credentials, refresh, and sticky routing. The toolkit owns lifecycle, compatibility checks, visibility, client setup, and policy or cooldown controls. A thin client holds a scoped gateway token and, for remote access, a tunnel service token — never the host's credential vault.
